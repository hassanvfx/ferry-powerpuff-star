# Goal

Preparar una V5 aislada para la corrida independiente de 90 páginas a 2K y 2:3, usando sin cambios los 90 prompts ya materializados en `libro/produccion/prompts-90/`.

# Task Contract

- Intended outcome: una configuración V5 lista para el gestor paralelo, con estado, recibos, salidas y snapshots propios; V5 apunta directamente al plan fuente y a los 90 prompts fuente existentes, sin reaprovechar ni reescribir los de V4.

En modo continuo emite un resumen JSON detallado por cheque, con intervalo configurable de 60 segundos, no permite dos ciclos mutantes simultáneos y registra como completados los PNG no vacíos presentes en disco al inicio de cada ciclo. # Decisions

- V5 no recibe un plan ni un snapshot copiados: lee el plan fuente y materializa snapshots propios sólo cuando un envío futuro autorizado invoque el ejecutor.
- El gestor conserva un bloqueo persistente ante falta de créditos: detecta el 402 tanto si el CLI lo devuelve por salida estándar como por error y no vuelve a enviar mientras ese bloqueo exista.
- Tras comprobar el saldo renovado y contar con autorización, se reinició el estado local V5 antes de enviar la tanda inicial 01–05; los recibos constituyen la fuente local de esos trabajos activos.
- La reanudación no requiere reiniciar índices: una nueva invocación vuelve a leer los recibos, PNGs y `estado.json`; sólo envía páginas sin recibo, sin PNG y que tengan cupo.
- La salida del operador se cambió a JSON indentado y ordenado. Cada cheque lista trabajos consultados, descargas, envíos, trabajos que excedieron el tiempo de cola, conteos completados/restantes, activos y fallidos.
- El lector de estado ahora acepta el JSON de Kie aunque `kie-cli job-status` termine con salida no cero. Las respuestas `failed` se archivan y programan para reintento; el reporte incluye código y mensaje del proveedor. Sólo una respuesta sin estado se conserva como error transitorio y se muestra en `status_errors`.
