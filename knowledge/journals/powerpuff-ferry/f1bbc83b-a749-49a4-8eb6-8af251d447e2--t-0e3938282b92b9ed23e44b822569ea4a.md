# Goal

Crear y probar en seco un orquestador aislado de dos etapas para las 90 páginas: primero una lámina guía basada en su prompt de storyboard y después el arte final usando el PNG guía como referencia adicional.

# Task Contract

- Intended outcome: `mantener_cola_paralela_guia.py` y la configuración V6 `corrida-90-2k-2-3-v6-guia` con almacenamiento separado para prompts, recibos y PNGs de guía y finales.
- Observable success criteria: para cada id, el gestor sólo puede enviar la fase final después de que exista un PNG guía no vacío; el comando final adjunta ese PNG además de las referencias aprobadas; modo seco verifica 90 pares y expone la siguiente fase sin llamadas remotas.
- Constraints and non-goals: no modificar prompts fuente, guía, plan, V3, V4 ni V5; no adjuntar página anterior; sólo usar las hojas v2 y la referencia de estilo aprobadas; no enviar una prueba real sin una autorización explícita de prueba que asume el coste de dos imágenes.
- Open questions and assumptions: se reutilizarán los modelos, 2K y 2:3 de V5 para ambas fases; las guías existentes en Markdown son los prompts auxiliares ya materializados y no se regenerarán.

- Se localizaron los 90 Markdown existentes en `prompts-guia-90/`; el plan fuente los enlaza mediante `production_guide` y su README define precisamente la secuencia guía antes de final.
- Se creó `corrida-90-2k-2-3-v6-guia.json` con directorios independientes para PNG, recibos y snapshots de guía y finales. La capacidad autorizada para la prueba actual es cinco trabajos activos.
- Se implementó `mantener_cola_paralela_guia.py`. La fase guía usa el Markdown de guía correspondiente y las referencias aprobadas. Sólo tras descargar un PNG guía no vacío la fase final lee el prompt fuente y adjunta ese PNG como tercera referencia, después de estilo y hoja de personaje aplicable.
- El gestor conserva reintentos por fase, bloqueo persistente por crédito insuficiente, caché de PNGs, recibos separados y candado de ejecución. No adjunta imágenes de páginas previas.
- El candado se calculó con la misma función que usa el gestor, sobre los bytes actuales ordenados de id, prompt final y guía de cada una de las 90 páginas. No se modificaron esas fuentes.
- Se añadió `--watch --interval-seconds 60`: una sola ejecución puede consultar la guía, descargarla y desencadenar después su final sin relanzar manualmente el proceso.
- El autor autorizó probar cinco páginas nuevas con sondeo de 30 segundos. El dry-run confirmó capacidad 5; la página 01 ya tiene salida final V6 y se excluye de esa tanda nueva.

# Decisions

- El sufijo operativo es `v6-guia`: nunca comparte estado ni almacenamiento con V5.
- Ambas fases usan `gpt-image-2`, 2K y 2:3; la guía no sustituye las referencias aprobadas, sino que se suma como dependencia visual para el arte final.
- La prueba local se limita a `--dry-run`. Una prueba real requiere al menos dos trabajos de Kie y permanece pendiente de una autorización explícita separada.
- `--watch` es parte del gestor `-guia`, no de V5, y mantiene el mismo límite de capacidad por ciclo.
