# Goal

Permitir correcciones declarativas y selectivas de una página final sin destruir la final de producción, y hacer que el visor publique la mejor versión disponible de cada página.

# Task Contract

- Intended outcome: un manifiesto versionado `libro/produccion/corridas/final-patches.json` y un operador manual que aplique sus parches habilitados a finales 2K (o 4K si se declara), guardando el resultado en `final-patched/`. Cada payload de parche adjunta únicamente la final elegida y un prompt breve de edición. El publicador prioriza por página `final-patched`, `finales-4k`, `finales-2k` y, para corridas heredadas, `finales`.
- Observable success criteria: un parche identifica una corrida y una página, conserva el PNG de origen, registra prompt y recibo, es reanudable tras un envío, y descarga sólo a `final-patched`. El manifiesto incluye el caso 20 y permite un dry-run sin red. La publicación mezcla capas por página según la prioridad declarada y conserva la validación de guías y de páginas consecutivas. Cumplido para la página 20: el globo superior resultante muestra «Yoshi».
- Constraints and non-goals: no cambiar prompts fuente ni reabrir una cola V11; no ejecutar parches automáticamente, cron o heartbeat; no tocar V3. Los PNG de origen nunca se sobrescriben. Un `replace_existing: true` explícito puede reemplazar sólo la derivada `final-patched` y archiva su recibo anterior. La llamada Kie real queda limitada al parche de página 20 autorizado por el autor.
- Open questions and assumptions: un único `final-patched/<id>.png` representa el parche vigente de una página. Si se requiere sustituir un parche existente, será una decisión explícita futura, no una sobreescritura silenciosa.

# Decisions

- El manifiesto será la fuente de intención de los parches masivos; el script conserva el modo de una imagen para diagnóstico puntual, pero el postpaso manual utiliza el manifiesto.
- `final-patched` es una capa de reemplazo por página, nunca un reemplazo del archivo final original.
- La resolución del manifiesto selecciona de forma estricta la salida homologada: `2K`→`finales-2k`, `4K`→`finales-4k`; el resultado mantiene esa resolución.
